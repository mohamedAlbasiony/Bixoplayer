# BixoPlayer — Premium Streaming Platform

A cinematic, responsive Vanilla JS streaming platform frontend with a backend-ready REST API and real-payment architecture.

## Included
- Cinematic fullscreen hero with local video slot + graceful fallback
- Dark / Light theme persisted in `localStorage`
- Movies, Series, Live TV, Sports and dynamic pricing cards
- Standard `$30/year` and Pro `$45/year` with `MOST POPULAR`
- Subscription modal and backend checkout flow
- REST API service layer using `fetch()`
- Stripe Checkout subscription architecture — no payment secrets in frontend
- Chatbot UI + `/api/chat` backend and AI-provider integration point
- WhatsApp / Telegram / Facebook centralized config
- Search overlay with loading/error/no-results states
- FAQ accordion, notifications, modals, mobile menu
- IntersectionObserver reveals, responsive layout, accessibility-friendly controls

## Run locally
1. Install Node.js 20+.
2. `npm install`
3. Copy `backend/.env.example` to `backend/.env` and set real server-side values.
4. `npm start`
5. Open `http://localhost:3000`.

## Real payment setup
Create Stripe Products/Prices in the Stripe Dashboard and place the resulting Price IDs in:
- `STRIPE_STANDARD_PRICE_ID`
- `STRIPE_PRO_PRICE_ID`

Put the secret only in `backend/.env`:
- `STRIPE_SECRET_KEY`

The frontend calls `POST /api/create-checkout`. The backend creates the Checkout Session and returns its URL. No fake success is generated by the frontend.

### Production webhook requirement
For a real production subscription lifecycle, add a Stripe webhook endpoint (for example `/api/webhooks/stripe`) that verifies the webhook signature and persists `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`, and invoice/payment events in your database. Do not activate entitlements based only on a frontend redirect.

## AI chatbot setup
The frontend calls `POST /api/chat` with:
```json
{"message":"What plans do you have?","sessionId":"..."}
```
The backend can call any AI provider by setting:
- `AI_PROVIDER_URL`
- `AI_API_KEY`

The key is read only by the backend. If no provider is configured, the backend uses clearly labeled fallback responses for local testing.

## Contact configuration
Update the public contact object in `js/config.js`:
```js
export const CONTACT_CONFIG = {
  whatsappSupportLink: 'https://wa.me/message/QXB5CJXUU6GYO1',
  telegram: 'YOUR_TELEGRAM_USERNAME',
  facebook: 'YOUR_FACEBOOK_URL'
};
```

The WhatsApp phone number is intentionally not stored in the frontend. Use the public `wa.me/message` support link instead.

## Content / video assets
Replace placeholder image URLs with your licensed posters. Put a licensed hero video at `assets/videos/hero.mp4`. The site works without it because the CSS fallback remains visible.

## Recommended production additions
- PostgreSQL/MongoDB persistence for users, subscriptions, orders, payments, chat sessions and support tickets
- Auth with secure HTTP-only cookies and server-side authorization
- Signed/protected video playback URLs or a video CDN
- Rate limiting, CSRF strategy where applicable, validation, audit logging and structured error monitoring
- Real provider webhook verification and idempotent subscription processing
- CDN/image optimization and lazy-loaded media

## Security rule
Never commit `.env`, payment secrets, AI keys, database credentials, or private tokens. Only commit `.env.example`.


## Theme system
The Dark/Light switch is global and uses CSS variables (`data-theme`) across the navbar, hero, sections, cards, pricing, modals, search, chatbot, and footer. The selected theme is persisted in `localStorage` under `bixo-theme`.


## WhatsApp Support Number

The WhatsApp number is configured in one place only: `js/config.js`. Replace `YOUR_WHATSAPP_NUMBER` with the international-format number **without `+`, spaces, or dashes**.

Example:

```js
export const CONTACT_CONFIG = {
  whatsappSupportLink: "https://wa.me/message/QXB5CJXUU6GYO1",
  telegram: "YOUR_TELEGRAM_USERNAME",
  facebook: "YOUR_FACEBOOK_URL"
};
```

All WhatsApp buttons—including Contact, Footer, Error Support, and the floating WhatsApp button—use this single configuration value.


### WhatsApp privacy
The frontend intentionally does not contain the WhatsApp phone number. All public WhatsApp buttons use the wa.me/message support link, so the phone number is not exposed in HTML attributes or frontend JavaScript. If a custom prefilled message is needed later, generate it server-side.
